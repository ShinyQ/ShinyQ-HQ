# AGENTS.md: conventions for ShinyQ HQ

Read this before changing anything. It applies to humans and AI agents in every build phase.

## Source of truth

- Design: `docs/superpowers/specs/2026-10-09-agent-hq-design.md` plus appendices `docs/superpowers/specs/agent-hq/01..08`. An appendix wins over the main spec for its topic.
- Owner content decisions C1 to C9 (appendix 07 section 7) override everything else about content.
- Phase plans live in `docs/superpowers/plans/`. Write one before starting a phase.

## Hard rules

- **No em dashes** (U+2014) anywhere: code, comments, copy, docs, commits, PR text. A unit test scans the repo. Use commas, colons, parentheses or "to".
- **No first person in mottos, taglines or titles (owner rule, 2026-10-13).** No "I", "my", "me" (EN) or "saya", "aku" (ID) in `profile.headline`, `profile.subheadline` (the motto), pod titles and taglines, post titles, page titles or OG card text. `hasFirstPerson` (`src/lib/first-person.ts`) enforces it for the headline and titles (`tests/content/first-person.test.ts`), page titles (`tests/unit/seo-copy.test.ts`) and share card text (`tests/unit/og-cards.test.ts`); the motto and every pod tagline by `tests/content/taglines.test.ts` (body text and stories keep the first person).
- **Public repo.** Never commit private evidence, private repository names, cloud resource names, phone numbers, addresses, ID numbers, money amounts, salary or review text, the Master's degree, 2026 hackathon entries or any photo (exception, owner decision 2026-10-13: the owner's own portrait, `public/og-assets/kurniadi-photo.png` for share cards and JSON-LD, and the web sizes under `public/brand/`).
- **No client company names (C3, revised 2026-10-10).** Clients of the owner's employers (for example the bank, automotive, bakery, mining, lender and insurer clients) never appear on the site: not in text, alt text, slugs, metadata, OG cards, JSON-LD, search, room views or 3D labels. Use a sector label instead (`Pod.client` as `{ en, id }`, e.g. "National digital bank" / "Bank digital nasional"). Employers stay named (Metrodata / PT Mitra Integrasi Informatika, Jenius (SMBC Indonesia) for the 2024 to 2025 job only, Jatis, MNC, internships), and so do the freelance clients in C8. Product names are allowed, including MII / Metrodata products (ARIA, Pris.AI, MII Fraud Detection, MII E-Recruitment, eVendor, MII Deck, MII AI Ticketing; ATLAS and FREDDY are client work, so they get a sector label); never claim a product the owner did not build (Deck Studio inside MII Cowork, not all of Cowork). Sole exception: the owner's CV PDF in `public/cv/`, committed byte for byte at the owner's request (it may list items the site text hides); never edit or regenerate it. Its page images in `public/cv/pages/` (rendered by `bun run cv:pages` for the CV viewer) share that exception; never OCR them into site text or alt text (alt text is "CV page N of M").
- **Content is data.** Pages, rooms, pods and missions are generated from `content/site-content.json`. Never hardcode career facts in components.
- **Bilingual.** Every user-facing content string is `{ en, id }`. Indonesian is natural and professional ("saya"), technical terms stay in English. UI strings live in `messages/en.json` and `messages/id.json` with identical keys.
- **Static export.** `output: "export"`: no server runtime, no middleware/proxy, no API routes, no `next/image` optimization. Every route must pre-render through `generateStaticParams` and set `dynamicParams = false` on dynamic segments.
- **Every route works without WebGL.** 3D (Phase 1+) mounts client-side on top of the HTML pages and must never replace their content.

## Content access

- Import from `@/content/load`: `getContent`, `getProfile`, `getStats`, `getSkills`, `getCertifications`, `getAwards`, `getPods(wing?)` (site order, `orderPods` in `@/content/selectors`: pods with a gallery first, then hero, featured, listed, then `order`), `getPod(slug)`, `getTimeline()` (oldest first), `getTimelineEntry(slug)`, `getTimelineEntryById(id)`, `getYears()` (year rooms; pre-2019 entries fold into 2019 as the prologue), `getPosts()`, `getPost(slug)`, `getLibrary()`, `getRoof()`, `getContact()`, `getSideProjects()`, `getPublicRepos()`, `getMissions()`, `tr(text, locale)`.
- Types come from `@/content/schema` (`Pod`, `TimelineEntry`, `Mission`, `MissionStep`, `RoomId`, `Locale`, ...). Do not redeclare them. Client code imports the locale values from `@/content/locales`, never values from `@/content/schema` (type-only imports are fine); `bun run build` fails otherwise.

## Content style

- **Title Case for titles** (owner decision 2026-10-12): pod, post (`site-content.json` and the MDX frontmatter `title`), publication, talk, side project, award and principle titles are stored in Title Case in both locales, never cased with CSS `text-transform`. ## Motion setting (owner decision, October 2026)

- Why: Windows reports `prefers-reduced-motion: reduce` whenever Settings > Accessibility > Visual effects > Animation effects is off, so on such a PC every elevator ride was the 150 ms cut and the whole HQ ran reduced. The owner chose a Motion setting (System / Full / Reduced, ID Sistem / Penuh / Dikurangi), default System.
- Model (`src/lib/motion.ts`, pure): `MotionPref`, `resolveReducedMotion(pref, systemReduced)` (System follows the OS, Full and Reduced override it). The store persists `motion` and keeps `reducedMotion` resolved, so every 3D consumer (rides, intro, holograms, boost, camera glides, the dialog typewriter) keeps reading `reducedMotion`; `Experience` still feeds the OS flag (`setReducedMotion` plus the `matchMedia` change listener). The store hydrates synchronously when it is created, before the first 3D frame, so the intro already follows the setting. `RoverTerminal` follows it too.
- Page CSS: `setMotion` and the head script set `html[data-motion="full|reduced"]` (removed under System). `globals.css` redefines Tailwind's `motion-reduce` and `motion-safe` variants on top of it (`@custom-variant`), so every `motion-reduce:` / `motion-safe:` utility and every `@variant motion-reduce { ... }` block (boot log, landing hero and ticker, Page View screenshots) applies under the OS setting unless `full`, and always under `reduced`. Write new reduce rules as `.x { @variant motion-reduce { ... } }`, never as a bare `@media (prefers-reduced-motion: reduce)` (top-level `@variant` blocks compile wrong, and `:is()` drops `::before` / `::after`, so the global duration rule is written out). The landing's "Pause motion" checkbox hides under the effective reduced motion like before.
- UI: `MotionMenu` (`src/hud/MotionControl.tsx`), a round icon button right of Sound in the 3D top bar (`data-testid="motion-menu"`, `data-onboard="motion"`), opens a small popover with `MotionChoices`: a fieldset of three native radios (legend "Motion", arrow keys move and select, Esc and an outside click close it and return focus). - Hint: `MotionHintLayer` (`src/hud/dialog/`) has Rover ask once per browser, after the first-session tour, when the OS reduces motion and the setting is still System ("Full motion" sets Full, "Keep reduced" or Esc keeps it; either answer sets `hq:motion-hint`). Never on the Classic site, never in the boot or intro. Copy: `dialog.motion`.
- Tests: `tests/unit/motion.test.ts`, `tests/unit/boot-first.test.ts`, `tests/hud/Controls.test.tsx`, `e2e/motion.spec.ts` (`page.emulateMedia({ reducedMotion: "reduce" })`: the cut under System, `lastRide.distinctY` at least 12 under Full, the moving intro under Full, Reduced without the OS flag, the hint, axe, Cmd-K on the Classic site).

## Point-and-go (owner request, October 2026)

- The rover never drives to a clicked floor point. Visitors drive with WASD or the arrows (Shift boost) or the joystick (boost button), or point at a glowing target: desktop hover highlights it (outline, destination ring, a name tag on a dark pill over the ring, pointer cursor) and a click drives there along the road and runs its action; on touch the first tap selects it (HUD "Go to ..." chip, aria-live text) and a second tap or Go drives. A click on empty floor only closes an open room, clears a tap selection and shows a hint once per session (`hq:point-hint`).
- Targets come from one registry, `src/experience/interact/registry.ts` (pure): `interactablesFor(floor, layouts, { experience, labels })` returns `Interactable` entries: `id`, `floor`, `kind` (`door`, `elevator-pad`, `teleporter`, `station`, `kiosk`, `board`), `label` (resolved for the tower's locale), `at` (approach point), `bounds`, `height`, `action` (`open-room`, `elevator-picker`, `teleport-picker` with `year`, `command`), optional `base` (bottom of the pick volume, for stacked targets such as the Tech Reactor rings). - New in-world targets: add them to `baseInteractables` (built-in floor content) or call `registerExtraInteractables(floor, items)` from the feature (it returns the dispose function; ids must be unique, and the built-in entry wins a clash). `extraInteractables(floor)`, `onInteractablesChange(listener)` and `useInteractables(floor, layouts, data)` read them; inside the canvas `interactRuntime.items` holds the current floor's full list. ## Fast verification

The full local suite takes 20 to 40 minutes on SwiftShader; most of it covers code you did not touch. Verify what you changed locally and let CI run everything.

- Before every push: `bun run verify:quick` (typecheck, lint, unit tests, `next build`, then `og:check` over the export, about 1 to 2 minutes), then `bun run e2e:changed` (only the specs that cover your changed paths, usually 1 to 4 minutes). Together about 5 minutes.
- Also run `E2E_PORT=<port> bun run e2e:perf` (3D bytes, floors, peaks, memory; about 8 to 10 minutes on 2 workers) when you change the render path, materials, floor mounting, the elevator or what the 3D chunk imports. `e2e:changed` never runs the perf lane.
- `e2e:changed` diffs against the merge base with `origin/main` plus staged, unstaged and untracked files and maps paths to specs in `scripts/e2e-plan.ts` (for example `src/experience/floors/labs/**` to `labs`, `gallery` and `walk`, `src/experience/interact/**` to `interact`, `experience`, `pads` and `career`, `src/experience/tower/**`, `scene/Director.tsx`, `scene/precompile.ts` and `text-config.ts` to `ride` and `experience`, `src/app/**` and `src/components/**` to `pageview`, `static-routes` and `gallery`, `src/hud/drawer/**` to the drawer specs, `drawer-solid` included, `src/hud/dialog/**` and `src/experience/hints/**` to `onboarding`, `experience`, `walk` and `camera`, `src/experience/camera/**` to `camera`, `experience`, `career` and `ride`, `src/experience/input/**`, the rover mesh, fade and runtime and `src/hud/ViewControls.tsx` to `camera` and `experience`, `Readable`, `HoloIcon`, the scene probes and `tower/FloorLevel.tsx` to `camera`, `career`, `experience` and `ride`, `src/experience/scene/{FrameLoop,framePacer,cover,coverWatch}`, `CanvasBoundary`, `recovery` and `tower/rideClock` to `lifecycle`, `experience` and `pads`, `fx/useDispose`, `scene/memoryProbe`, `scene/sharedResources` and floor mounting (`tower/{Tower,near,FloorLevel}`) to `memory` and `experience`). Changes to `e2e/hq.ts`, `playwright.config.ts`, `package.json`, `bun.lock` or `next.config.ts` run the full suite; unmapped paths add the smoke specs; docs and unit tests run nothing. `--dry` prints the plan, `--base <ref>` changes the base, extra args go to Playwright (`bun run e2e:changed --headed`). When you add a spec or a folder, add its rule (a unit test checks every spec is known).
- `bun run bench` runs the Vitest benches in `tests/bench/` (path finding on the real layouts, palette typing) against frozen copies of the old code in `tests/helpers/*-legacy.ts`; use it for CPU changes and paste the table into the PR.
- `bun run e2e:smoke` (static routes, SEO, deploy rules, game-first load, Page View, about 1 to 2 minutes) is the fallback when unsure. `bun run e2e:full` (whole suite, about 6 to 10 minutes locally) only when you change shared test infrastructure, before a phase PR, or to reproduce a CI failure locally (`bun run e2e:full e2e/career.spec.ts -g "swipe"`).

Artifacts: `screenshots`.
- Look-preserving changes (render budget, batching, visibility, anything that may move pixels): `E2E_PORT=<port> bun scripts/visual-gate.ts --base HEAD --profile strict|msaa|batching|release` builds the base ref in a sibling worktree, `--head <ref>` compares another commit instead of the working tree (builds are cached per commit in sibling worktrees), captures 3 devices (full 1440x900@2, full 2560x1440@1, lite 390x844) x 8 poses at fixed frame counts with a virtual frame clock (`e2e/vclock.ts`), on the real GPU on macOS (ANGLE Metal; `VISUAL_GATE_GPU=swiftshader` for the CI renderer), and compares the working tree build within the profile's thresholds (strict: per-pixel 0.1, at most 0.1% of pixels). About 20 minutes on an M-series Mac plus builds; one run at a time. `--self` measures the harness noise. GPU timings on a real GPU: `bun scripts/perf-gpu.ts sp4|sp9` (results in `docs/perf/r5-gpu.md`).
- Workers: Playwright uses 2 workers locally and on each CI shard (4 vCPU runners). Every worker renders WebGL on the CPU, so more workers starve each other and make 3D tests time out; do not raise it. Do not run two e2e suites at once on one machine.
- Turbopack can serve stale CSS after large style or dependency changes: `rm -rf .next` before `verify:quick` if the export looks wrong. `e2e:*` serves `out/` from the last build, so rebuild after code changes (`verify:quick` does).
- Writing 3D tests: wait on state, never on time. Use the helpers in `e2e/hq.ts`: `enterHQ`, `enterFloorRoute` (deep link, waits for the scene loop), `waitForSceneLive` (the phase is `explore` before the first frame on deep links, and input sent earlier is dropped), `waitForCameraSettle` (counts rendered frames, so a stalled main thread does not look settled), `waitForFrames`, `waitForFloor`, `waitForRoom`, `waitForRoverMove`, and `expect.poll` for values. On static pages, `openPage(page, url)` (or `waitForHydration` after a reload or full navigation) before clicking client islands: the Next.js chunks load after first paint, so `load` fires before hydration (signal: `html[data-hydrated]`, set by `MissionHud`). `page.waitForTimeout` is only for proving that nothing happens (for example that `?tier=static` never mounts the canvas). Pass `?tier=lite` (no bloom or motes) unless the test is about the full tier. No blanket retries: CI retries once; fix a flaky test instead of adding retries.
- CI shards with `scripts/e2e-shard.ts` (round-robin over `playwright test --list`, so every shard gets part of every slow 3D spec; Playwright's own `--shard` cuts contiguous blocks). Shards upload blob reports that `Build, CV and e2e` merges into the `playwright-report` artifact. To reproduce a shard locally: `bun run e2e:shard 2/4`.
