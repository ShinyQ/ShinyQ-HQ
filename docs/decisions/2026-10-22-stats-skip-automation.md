# Public visit stats

- Date: 2026-10-22

Owner decision after a check of the live Visits panel: automated browsers are never counted, and counts read correctly. Every beacon skips a browser that sets `navigator.webdriver` (Playwright, Lighthouse, headless checks): the first-party visit beacon and the RUM beacon already did (only `?visit=1` and `?rum=1` force them in tests), and the Cloudflare Web Analytics loader now returns before it injects `beacon.min.js`, the same way the opt-out stops it (nothing forces it). Ask questions from such browsers are still answered, but the client sends `auto: true`, the handler logs blob13 `auto` and the `hq-stats` Worker leaves those rows out of the public question counts; the flag is for counting only and never feeds a safety, limit or Turnstile decision. Opt-out, Do Not Track and GPC behave as before. The panel's counted sentences use ICU plurals ("1 pick", "1 visit from 1 country, 1 question"; the office "1 job" too), and the 3D vs Classic split's note says it is the share of visits the site's own beacon saw, so its base (79 beacon visits at the time) is smaller than the Web Analytics visit total (160). A look at the raw Web Analytics data (10 to 21 Oct) added two copy fixes: Web Analytics samples page loads (sample interval 10), so the source line now says "Cloudflare Web Analytics, sampled, rounded to tens" (small counts move in steps of 10 and a quiet day can read 0); and the country list counts a country with at least one sampled page view (some countries had page views but 0 sampled visits), so the map and table captions say "page view" instead of "visit" rather than dropping those countries.
