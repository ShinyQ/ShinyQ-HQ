# CI

- Date: 2026-11-01

CI audit (owner request: "I need you to audit our CI too since its takes so long can you maybe think which was really needed to stay n which is needs to be removed"). Evidence from 123 CI runs (2026-10-23 to 2026-10-31): 26 of 50 green PR runs used the full set of shards (22.1 min median), 12 of them forced only by files that cannot change a test result (other workflows, the e2e spec map); the 3D perf lane finished last in 22 of 26 full PR runs and 20 of 21 long `main` runs; 26 perf retries (2.3 runner-hours) were invisible because the flaky report covered only the e2e lane; the Screenshots nightly was red 15 of 15 nights. No job is removed: every gate caught a real regression in the window. Owner approved all recommended changes plus two gate and process changes. C1: only `ci.yml` and `.github/actions/` (with the dependency, config and runner files) force a full run; other workflows are `docs`, and a change to the spec maps (`scripts/e2e-plan.ts`, `scripts/perf-plan.ts`) runs the PR's selective plan plus every spec and perf key whose mapping changed (the base and head maps compared over every tracked file; any failure plans a full run). C2: every run has at most 10 e2e plus perf shards (a full run 6 e2e and 4 perf, the nightly too), so a `main` run peaks at 12 jobs instead of 14; `e2e/durations.json` refreshed. C3: Lighthouse runs in 2 shards when it checks 4 or more URLs on a run with at most 8 e2e plus perf shards (a selective run, where it finished last in 10 of 21 runs; a full run keeps 1, its e2e and perf shards outlast it); a small `Lighthouse CI` job keeps the required check name, merges the reports and fails unless every shard passed. C4: the perf shards upload their blob reports and the aggregate job lists perf tests that passed only on retry, like e2e tests. C5: one selective PR run may share with a `main` run (12 + 1 Deploy + 7 = 20). C6: the Screenshots nightly opens, updates and closes one `screenshots-nightly` issue like `ci-nightly`. C7: the always-skipped `preview` job is removed. G1: the eight extra L1 perf poses (the Needs Kurniadi beacon, the office in view, the Agent Office stop and the day replay, full and lite; 2,742 of 7,669 perf worker-seconds) end their titles with ` @nightly`: the nightly runs them, and so does a pull request that changes the Lobby or the office; pull requests otherwise and `main` skip them (the timeline perf tests move to their own `@timeline` tag). G2: agents bring a PR up to date with `main` and wait for its CI before handing it to the owner, so the merge takes the 4 min deploy fast path (15 of 52 deploys waited 27.4 min median for a full `main` run). Dropped: a scripts-only `package.json` rule (none of the 3 `package.json` PRs in the window would have planned selectively). Expected: average PR run 16.1 to about 11.5 min, full PR and `main` runs about 17 to 18 min, no wait for a `main` run before the next PR push. Audit: `docs/superpowers/plans/2026-11-01-ci-audit.md`.
