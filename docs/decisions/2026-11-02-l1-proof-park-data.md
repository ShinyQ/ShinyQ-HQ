# L1 Lobby: Proof Park contribution data

- Date: 2026-11-02
- PR: [#381](https://github.com/ShinyQ/ShinyQ-HQ/pull/381)

Owner request: square off the L1 floor around the Agent Office with new landmarks (the L1 Proof Park design). Its first part is the data for Contribution City, a landmark that draws the last year of the owner's GitHub contributions as one tower per day (GitHub's contribution graph in 3D, 53 week columns by 7 weekday rows). Tower colors use GitHub's own five contribution levels (owner choice), and tower heights come from the real daily counts on a log scale (owner change after reviewing the data: with GitHub's levels only 16 days sit above level 1, so level heights would read flat). The weekly live-facts refresh (`scripts/refresh-facts.ts`) now asks GitHub GraphQL for the daily calendar in the same request as the total and stores it in `content/generated/dynamic-facts.json` as `github.calendar`: the first date, one level digit (0 to 4) per day and one count per day (about 1.3 KB for 366 days; numbers, a date and digits only, no third-party text). The schema requires a real start date, 358 to 378 days, equal lengths, level 0 exactly on the days without a contribution, and counts that add up to `contributionsLastYear`, so the sign ("N contributions in the last year", from the existing fact) and the drawer's computed total always agree. The total and the calendar travel together: a missing or invalid calendar, or a total the drop guard refuses, keeps the previous pair and warns. Client-safe pure helpers in `src/lib/contributions.ts` derive what the floor needs (each day's place on the graph with its count and level, the total, the busiest day, the longest streak, days per level); the log height scale belongs to the floor code. Seeded on 2026-11-02 from the public calendar: 2025-11-02 to 2026-11-02, 9,670 contributions, busiest day 2026-08-30 (642), longest streak 85 days (2026-08-10 to 2026-11-02), days per level 126 / 224 / 8 / 4 / 4, which match the levels on the public profile graph.
