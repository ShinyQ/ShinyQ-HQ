# Fast PR CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Status: in progress (2026-10-18). Owner decision: option C (affected tests on PRs, full suite with 8 e2e + 4 perf
shards on main and nightly; deploys still require a complete green main run).

**Goal:** A typical pull request (a HUD change, an L3 floor change) finishes CI in about 10 minutes instead of about
25, while pushes to `main` and the nightly still run everything, faster, on 8 e2e and 4 perf shards.

**Architecture:** The `Plan CI` job (`scripts/ci-plan.ts`) already classifies changed paths. It grows three selectors:
e2e specs for every class (3D included) plus a small PR smoke set, with a shard count sized from `e2e/durations.json`;
a perf selector (`scripts/perf-plan.ts`) that maps paths to perf tests (bytes, per-floor gates, rides, boot, hover,
boost, memory) and passes them as a Playwright `--grep`; and a Lighthouse selector that maps paths to the
`lighthouserc.json` URLs through the static import closure of the app routes. `ci.yml` reads the shard lists from
the plan (dynamic matrices); PR perf keeps 2 shards so the required checks `3D perf gates 1/2` and `2/2` keep their
names, while non-PR runs use 4.

**Tech Stack:** Bun scripts, Vitest, GitHub Actions, Playwright, LHCI.

## Global Constraints

- No em dashes (U+2014) anywhere: code, comments, docs, commits, PR text.
- Required check names stay valid on PRs: `Typecheck, lint, unit tests`, `Build, CV and e2e`, `Lighthouse CI`,
  `3D perf gates 1/2`, `3D perf gates 2/2`. Heavy jobs never skip at the job level; their steps skip and a
  `Not needed` step passes.
- Always on, every event: typecheck, lint, unit tests, secret scan, build, public-safety scan of `out/`, CSP hashes
  (part of the build), `og:check`.
- Pushes to `main`, `workflow_dispatch`, the nightly schedule (`15 20 * * *`), any planner failure, a `full-ci` PR
  label, a changed CI/dependency/test-helper file, or a changed path the e2e rules cannot map: full run.
- Full runs on non-PR events: 8 e2e shards and 4 perf shards (duration-balanced, `scripts/e2e-shard.ts`). A full
  PR run: 8 e2e shards and 2 perf shards (required names).
- The `ci-full` artifact is uploaded only when every e2e test, every perf test and every Lighthouse URL ran;
  `deploy.yml` keeps reusing only complete green runs (`scripts/ci-status.ts`, unchanged).
- PR e2e shard count: `clamp(ceil(estimatedWorkerSeconds / (2 * 240)), 1, 8)`; unknown specs count 150 s.
- No budget, threshold or test is changed by this plan.

```ts
// scripts/perf-plan.ts
export const FLOORS = ["L1", "L2", "L3", "L4", "RF"] as const;
export type Floor = (typeof FLOORS)[number];
export type PerfKey = "bytes" | "boot" | "hover" | "boost" | "memory" | `floor:${Floor}` | `ride:${Floor}`;
export const ALL_PERF_KEYS: readonly PerfKey[];             // every key, memory included
export const ALL_BUT_MEMORY: readonly PerfKey[];
/** Keys a set of 3D-relevant files needs. Files that match no rule get ALL_BUT_MEMORY. */
export function perfKeysFor(files: readonly string[]): PerfKey[]; // sorted, unique
/** Playwright --grep for the keys; "" when the keys are every key (run the whole lane). */
export function perfGrep(keys: readonly PerfKey[]): string;

// scripts/e2e-plan.ts
export const PR_SMOKE: readonly { spec: Spec; title?: string }[];
/** 1-based line of the first `test(` call whose title string equals `title`, or null. */
export function locateTest(source: string, title: string): number | null;
/** Estimated worker-seconds of a spec (sum of its durations), or of one test when `title` is given. */
export function specSeconds(durations: Durations | null | undefined, spec: string, title?: string): number;
export const UNKNOWN_SPEC_SECONDS = 150;
export const UNKNOWN_TEST_SECONDS = 30;
```

### Task 2: Planner: affected e2e, perf and Lighthouse selection, shard counts

**Files:**
- Modify: `scripts/ci-plan.ts`
- Test: `tests/unit/ci-plan.test.ts`

**Interfaces (consumes Task 1; produces outputs read by Task 3):**

```ts
export interface PlanOptions {
  event?: "pull_request" | "other";                         // default "pull_request" when files != null
  durations?: Durations | null;                              // e2e lane of e2e/durations.json
  locate?: (spec: Spec, title: string) => number | null;     // line of a smoke test in e2e/<spec>.spec.ts
  pages?: (file: string) => readonly string[] | "all";       // Lighthouse URL paths a file can move ([] = none)
  fullLabel?: boolean;                                       // the PR carries the full-ci label
}
export interface CiPlan {
  full: boolean;
  e2e: "all" | Spec[];
  e2eTests: string[];          // extra `e2e/<spec>.spec.ts:<line>` filters (smoke tests), only for spec lists
  e2eShards: number;           // 1..8; 8 for "all"
  perf: false | PerfKey[];     // false: no perf; ALL_PERF_KEYS: the whole lane
  perfShards: number;          // 2 on pull requests, 4 otherwise
  lighthouse: false | "all" | string[];  // URL paths such as "/en/quick"
  classes: Partial<Record<ChangeClass, string[]>>;
  reasons: string[];
}
export function planFor(files: readonly string[] | null, in3d: (f: string) => boolean, opts?: PlanOptions): CiPlan;
export function planOutputs(plan: CiPlan): Record<string, string>;
export const LIGHTHOUSE_PAGES: Readonly<Record<string, string>>; // URL path -> page file
```

`planOutputs` keys (strings): `full`, `e2e` (`all|specs|none`), `e2e_files` (space-separated spec files and
`file:line` filters), `e2e_shards` (JSON array `[1,...,n]`), `e2e_total`, `perf` (`true|false`), `perf_grep`,
`perf_shards`, `perf_total`, `lighthouse` (`true|false`), `lighthouse_urls` (JSON array of full LHCI URLs with the
warm-up URL first, or `""` for every URL). `full` is `"true"` only when e2e is `all`, perf is every key and
Lighthouse is `all`.

Rules:
- `files === null`, non-PR event, `fullLabel`, `ci`/`other` class: full (e2e all, perf every key, Lighthouse all).
  e2eShards 8; perfShards 4 for non-PR events, 2 for PRs.
- e2e: e2e helper changed (non-spec `e2e/` file) -> all; else `specsForChanges` over every non-docs, non-tests
  file; any `unmatched` -> all (reason lists them); add `PR_SMOKE` when `code3d` or `ui` changed (whole specs
  join `e2e`, titled tests become `e2eTests` unless their spec is already selected; a title `locate` cannot find
  is dropped with a reason line). Shards: `all` -> 8; none -> 1; else
  `clamp(ceil(sum(specSeconds) / (2 * 240)), 1, 8)`.
- perf: `perfKeysFor` over the `code3d` files plus `ui` files the 3D roots import (`in3d`); none -> false.
- Lighthouse: for every `code3d`, `ui` and `content` file, `pages(file)`; union; `"all"` wins; empty -> false.
  Default `pages` (tests, no closure): `ui`/`code3d` -> `"all"`, `content` -> `[]`.

In `main()`: read `e2e/durations.json`; `locate` reads `e2e/<spec>.spec.ts`; fetch PR labels with
`GET /repos/{repo}/issues/{pr}/labels` (a failure means no label); `pages` from static import closures:
`importClosure(roots, read, { dynamic: false })` (skip `import()` matches) of the layouts
(`src/app/[locale]/layout.tsx`, `src/app/(root)/layout.tsx`) -> `"all"`, then per `LIGHTHOUSE_PAGES` page file ->
that URL path; non-`src/` files: `messages/`, `public/(fonts|brand)/`, the `ui` scripts, `content/site-content.json`,
`content/generated/` (except `build-facts.json` -> `/en/build`) -> `"all"`; `content/posts/` -> the blog URL;
anything else -> `[]`.

`LIGHTHOUSE_PAGES`: `/en` and `/id` -> `src/app/[locale]/page.tsx`; `/en/quick`, `/en/journey`, `/en/contact`,
`/en/cv`, `/en/build` -> their `page.tsx`; `/en/labs/voice-ai-contact-center` -> `src/app/[locale]/labs/[slug]/page.tsx`;
`/en/blog/making-a-voice-agent-interruptible` -> `src/app/[locale]/blog/[slug]/page.tsx`. A unit test asserts the
keys equal the non-warm-up URLs in `lighthouserc.json`.

- [ ] Step 1: update and add tests: HUD file -> e2e specs plus smoke, perf `["bytes"]`, 1 to 2 e2e shards with the
  real durations; L3 file -> L3 specs plus smoke, perf L3 keys; functions -> `["ask"]`, no perf, no Lighthouse,
  no smoke; docs -> nothing; push (`files` null) -> 8/4 shards and `full: "true"`; `fullLabel` -> full with
  perfShards 2; unmapped `src/` file -> e2e all; outputs shape for each.
- [ ] Step 2: implement; run `bunx vitest run tests/unit/ci-plan.test.ts tests/unit/e2e-plan.test.ts tests/unit/perf-plan.test.ts`
  and `EVENT=push bun scripts/ci-plan.ts`; commit `feat(ci): affected-tests plan with sized shards`.
